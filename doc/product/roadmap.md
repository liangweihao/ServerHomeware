## 三、下一阶段 Epic（Near-term）

### Epic E1：首页通知与提醒统一

| 项 | 内容 |
|----|------|
| **Problem** | AppBar 🔔 与提醒 Tab 职责重叠，用户点击通知图标仅见占位，降低信任感。 |
| **Solution** | 通知中心抽屉/全屏页，聚合系统通知、提醒摘要、已读状态；与 `/alerts` 数据一致。 |
| **Personas** | 家庭管理员（妈妈/主理人），需快速扫一眼「今天要处理什么」。 |
| **功能需求** | 未读数与 Tab Badge 同步；点击跳转对应提醒；支持全部已读；空状态引导至提醒 Tab。 |
| **非功能** | 打开 ≤ 300ms；离线可读本地 Drift；a11y：列表可键盘/读屏遍历。 |
| **成功指标** | 通知入口点击率 ↑30%；提醒 Tab 跳转率 ↑15%。 |
| **Out of Scope** | 站外推送（微信/短信）、营销类通知。 |
| **业务价值** | 高 — 直接提升「省心」核心价值。 |

### Epic E2：提醒实时同步

| 项 | 内容 |
|----|------|
| **Problem** | Celery 已算提醒，但客户端依赖本地轮询/同步，多设备间提醒延迟。 |
| **Solution** | WebSocket 推送提醒变更 → 客户端更新 Drift → Badge 刷新。 |
| **依赖** | 现有 `/ws` 通道、`ItemSyncService` |
| **成功指标** | 跨设备提醒延迟 P95 < 5s。 |
| **Out of Scope** | 操作系统级 Push（FCM/APNs）— 可单列 Epic。 |
| **业务价值** | 中 — 家庭协作体验。 |

### Epic E3：盘点任务（轻量）

| 项 | 内容 |
|----|------|
| **Problem** | 用户难以定期核对「账实相符」，vision 强调容忍模糊 + 定期盘点。 |
| **Solution** | 按空间生成待核对清单，逐项确认/修正/跳过，完成后出简短报告。 |
| **成功指标** | 月活用户中 ≥ 10% 完成一次盘点。 |
| **Out of Scope** | RFID、IoT 自动盘点。 |
| **业务价值** | 中 — 提升数据可信度。 |

### Epic E4：录入增强（方式选择页）

| 项 | 内容 |
|----|------|
| **Problem** | 仅扫码 + 手填，录入成本仍是 vision 中最大痛点。 |
| **Solution** | FAB 点击 → 方式选择（扫码 / 手动 / 拍照 OCR* / 语音*）；* 为子 Epic。 |
| **用户旅程** | 物品 Tab → FAB → 选择 → 最短路径入库（目标 ≤ 15s）。 |
| **Out of Scope** | 电商订单同步（阶段 3 独立 Epic）。 |
| **业务价值** | 高 — 降低录入门槛。 |

**建议排期**：

```
Q3 2026  E1 通知统一 → E2 提醒同步
Q4 2026  E4 录入方式选择（含 OCR 子项评审）
2027 H1  E3 盘点任务
```
