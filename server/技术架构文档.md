# 家庭物品管理系统 - 服务端技术架构文档

## 1. 架构概述

### 1.1 整体架构

本系统采用经典的分层架构设计，遵循RESTful API规范，支持多用户协作和数据同步。

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   客户端    │────▶│   API网关   │────▶│   应用层    │
│  (Flutter)  │     │  (Nginx)    │     │  (Django)   │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                                               ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Redis     │◀────│  Celery     │◀────│   业务层    │
│  (缓存)     │     │  (任务队列)  │     │  (Services) │
└─────────────┘     └─────────────┘     └─────────────┘
                                               │
                                               ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   MySQL     │◀────│  ORM层      │◀────│   数据层    │
│  (数据库)   │     │  (Django)   │     │ (Models)    │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 1.2 技术选型理由

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| Django | 4.2.7 | 成熟稳定的Web框架，内置ORM、认证系统，开发效率高 |
| DRF | 3.14.0 | 强大的REST API框架，支持序列化、认证、权限控制 |
| MySQL | 8.0 | 关系型数据库，支持事务、外键约束，适合复杂查询 |
| Redis | 7.0 | 内存数据库，用于缓存、会话管理、任务队列 |
| Celery | 5.3.4 | 分布式任务队列，支持定时任务、异步处理 |
| JWT | - | 无状态认证，便于水平扩展和移动端集成 |
| Docker | - | 容器化部署，环境一致性，便于CI/CD |

## 2. 模块设计

### 2.1 用户模块 (apps/users)

**职责**：
- 用户认证与授权
- 家庭管理
- 权限控制

**核心功能**：
1. 用户注册/登录
   - 密码加密存储（bcrypt）
   - JWT Token生成与验证
   - 邮箱验证（预留接口）

2. 家庭管理
   - 创建家庭（自动生成邀请码）
   - 加入家庭（通过邀请码）
   - 家庭成员角色管理（管理员/成员）

3. 权限控制
   - 基于家庭的权限隔离
   - 角色权限区分

**API端点**：
```
POST   /api/auth/register/          # 用户注册
POST   /api/auth/login/             # 用户登录
GET    /api/auth/profile/           # 获取用户信息
PUT    /api/auth/profile/update/    # 更新用户信息
GET    /api/auth/families/          # 获取家庭列表
POST   /api/auth/families/          # 创建家庭
GET    /api/auth/families/{id}/     # 获取家庭详情
POST   /api/auth/families/{id}/join/# 加入家庭
```

### 2.2 物品管理模块 (apps/items)

**职责**：
- 物品CRUD操作
- 分类与位置管理
- 搜索与筛选

**核心功能**：
1. 物品管理
   - 添加/编辑/删除物品
   - 物品图片上传
   - 条形码扫描（预留接口）

2. 分类管理
   - 创建自定义分类
   - 分类图标和颜色
   - 分类统计

3. 位置管理
   - 支持层级位置（父子关系）
   - 位置描述
   - 位置统计

4. 搜索与筛选
   - 全文搜索（名称、描述、条形码）
   - 多条件筛选（分类、位置、家庭）
   - 排序功能

**API端点**：
```
GET    /api/items/                  # 获取物品列表
POST   /api/items/                  # 添加物品
GET    /api/items/{id}/             # 获取物品详情
PUT    /api/items/{id}/             # 更新物品
DELETE /api/items/{id}/             # 删除物品
POST   /api/items/batch-delete/     # 批量删除物品
GET    /api/items/categories/       # 获取分类列表
POST   /api/items/categories/       # 创建分类
GET    /api/items/locations/        # 获取位置列表
POST   /api/items/locations/        # 创建位置
```

### 2.3 库存管理模块 (apps/inventory)

**职责**：
- 库存监控
- 预警管理
- 报表生成

**核心功能**：
1. 库存预警
   - 低库存预警（数量≤3）
   - 过期物品预警
   - 即将过期预警（7天内）
   - 预警解决机制

2. 库存报表
   - 总体统计（物品总数、总价值）
   - 分类统计（按分类分组统计）
   - 位置统计（按位置分组统计）
   - 异常统计（低库存、过期数量）

3. 采购建议
   - 基于库存状态的智能建议
   - 优先级排序（高/中/低）
   - 建议数量计算

4. 库存日志
   - 记录所有库存变更
   - 操作类型追踪（添加、更新、删除、消耗、补货）
   - 数量变化记录

**API端点**：
```
GET    /api/inventory/alert/        # 获取库存预警
POST   /api/inventory/alert/resolve/# 解决预警
GET    /api/inventory/report/       # 获取库存报表
GET    /api/inventory/suggestions/  # 获取采购建议
GET    /api/inventory/logs/        # 获取库存日志
POST   /api/inventory/logs/log-action/# 记录库存操作
```

### 2.4 数据同步模块 (apps/sync)

**职责**：
- 多设备数据同步
- 冲突检测与解决
- 离线数据支持

**核心功能**：
1. 同步机制
   - 全量同步（首次同步）
   - 增量同步（基于时间戳）
   - 双向同步

2. 冲突处理
   - 自动冲突检测
   - 冲突类型分类（更新冲突、删除冲突、版本冲突）
   - 多种解决方案（服务器优先、客户端优先、手动处理）

3. 同步记录
   - 同步历史追踪
   - 同步状态监控
   - 错误日志记录

**API端点**：
```
POST   /api/sync/initiate/         # 发起数据同步
POST   /api/sync/upload/           # 上传客户端数据
GET    /api/sync/records/          # 获取同步记录
GET    /api/sync/conflicts/        # 获取同步冲突
POST   /api/sync/conflicts/resolve/# 解决同步冲突
```

### 3.2 表结构说明

#### users表
```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    phone VARCHAR(20),
    avatar VARCHAR(255),
    is_verified BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_username (username)
);
```

#### families表
```sql
CREATE TABLE families (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    invite_code VARCHAR(20) UNIQUE NOT NULL,
    created_by INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (created_by) REFERENCES users(id),
    INDEX idx_invite_code (invite_code)
);
```

#### items表
```sql
CREATE TABLE items (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    category_id INT,
    location_id INT,
    quantity INT NOT NULL DEFAULT 1,
    unit VARCHAR(20) NOT NULL DEFAULT '个',
    expiry_date DATE,
    purchase_date DATE,
    price DECIMAL(10,2),
    image VARCHAR(255),
    barcode VARCHAR(100),
    family_id INT NOT NULL,
    created_by INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (category_id) REFERENCES categories(id),
    FOREIGN KEY (location_id) REFERENCES locations(id),
    FOREIGN KEY (family_id) REFERENCES families(id),
    FOREIGN KEY (created_by) REFERENCES users(id),
    INDEX idx_family_category (family_id, category_id),
    INDEX idx_family_location (family_id, location_id),
    INDEX idx_expiry_date (expiry_date),
    INDEX idx_name (name)
);
```

## 4. 安全设计

### 4.1 认证与授权

1. **JWT认证**
   - Access Token有效期：60分钟
   - Refresh Token有效期：1440分钟（24小时）
   - Token轮换机制
   - Token黑名单

2. **密码安全**
   - 使用bcrypt加密存储
   - 密码复杂度验证
   - 防止暴力破解（速率限制）

3. **权限控制**
   - 基于家庭的权限隔离
   - 角色权限区分（管理员/成员）
   - API级别权限验证

### 4.2 数据安全

1. **传输安全**
   - HTTPS加密传输
   - 敏感数据脱敏
   - 请求签名验证（预留）

2. **存储安全**
   - 密码加密存储
   - 数据库连接加密
   - 定期备份

3. **防护措施**
   - SQL注入防护（ORM）
   - XSS防护（输入验证）
   - CSRF防护（Token验证）
   - 请求速率限制
